# GOLDILOCKS Monitor / goldilocks Admin

GOLDILOCKS 클러스터의 상태·리소스·SQL·세션·대기 이벤트를 확인하는 **Java 8 기반 웹/TUI 모니터**입니다. DB 서버에 모니터링 에이전트를 설치하지 않고 외부 관리 PC 또는 별도 서버에서 실행합니다.

이 저장소는 실행 패키지·체크섬·사용법만 공개 배포합니다. 개발용 Java 소스와 비공개 소스 저장소의 Git 이력은 포함하지 않습니다.

## 1. 준비

- **Java 8 이상(JRE)**과 웹 브라우저가 필요합니다.
- 압축을 해제한 후 실행합니다. 쓰기 가능한 폴더를 사용하십시오.
- 실행에 JDK·컴파일러·Python·Node.js는 필요하지 않습니다.
- JDBC 드라이버와 필요한 라이브러리·라이선스 문서는 패키지에 포함됩니다.
- 배포 기본값은 **mock 모드·127.0.0.1:19090**이며 실제 DB에 접속하지 않습니다. 실제 접속정보·비밀번호·수집 이력은 포함하지 않습니다.

## 2. 웹 실행

### Windows

1. ZIP을 다운로드하고 압축을 풉니다.
2. `java -version`으로 Java 8 이상인지 확인합니다.
3. `goldilocks-monitor` 폴더의 **`run-web.cmd`**를 더블클릭합니다.
4. 실행 창에 표시된 주소를 브라우저에서 엽니다. 기본 주소는 **http://127.0.0.1:19090**입니다.

다른 INI를 지정하려면 명령 프롬프트에서 실행합니다.

```bat
run-web.cmd C:\monitor\my-monitor.ini
```

`java`를 찾을 수 없다면 Java 실행 경로를 PATH에 추가하거나 JAVA_HOME을 설정하십시오. 실행 스크립트는 JAVA_HOME이 있으면 해당 Java를 사용합니다.

### Linux

```sh
tar -xzf goldilocks-monitor-linux.tar.gz
cd goldilocks-monitor
sh run.sh
```

다른 설정 파일도 지정할 수 있습니다.

```sh
sh run.sh /path/to/my-monitor.ini
```

직접 JAR로 실행하려면 압축을 푼 폴더에서 다음을 사용합니다. `build/`와 `lib/`의 상대 위치는 유지하십시오.

```sh
java -jar build/goldilocks-monitor.jar monitor.ini
```

브라우저 탭을 닫아도 수집 프로그램은 실행 상태를 유지합니다. 프로그램을 종료할 때는 실행 터미널에서 **Ctrl+C**를 누릅니다. 이미 19090 포트를 사용하는 프로그램이 있으면 INI의 포트를 바꿉니다.

## 3. 실제 GOLDILOCKS 연결

웹용 `monitor.ini`에서 mock을 jdbc로 바꾸고 실제 리스너 주소와 조회 계정을 설정합니다.

```ini
[monitor]
mode = jdbc
name = GOLDILOCKS Cluster
bind = 127.0.0.1
port = 19090

[collection]
interval_seconds = 3
retention_days = 31
data_dir = ./output

[goldilocks]
url = jdbc:goldilocks://<접속호스트>:<리스너포트>/test
user = <모니터링계정>
password =
```

수집에 사용하는 계정은 필요한 클러스터·시스템 통계 뷰를 조회할 수 있어야 합니다. 권한이나 버전에 따라 조회할 수 없는 지표는 N/A 또는 수집 오류로 표시될 수 있습니다.

웹 수집 비밀번호는 기존 INI 방식 또는 `MONITOR_DB_PASSWORD` 환경변수로 전달합니다. 웹의 기존 인증 방식은 유지됩니다. 비밀번호를 공개 저장소에 올리지 마십시오.

Linux 환경변수 예시:

```sh
read -r -s -p 'DB password: ' MONITOR_DB_PASSWORD
export MONITOR_DB_PASSWORD
printf '\n'
sh run.sh
```

INI 변경은 수집 프로세스를 재시작한 뒤 적용합니다. 상대 경로는 INI 위치를 기준으로 해석합니다. 다른 PC에서 웹에 접속해야 한다면 운영 환경의 접근 제어를 구성한 뒤 bind 값을 조정하십시오. 기본 대시보드 HTTP 화면에는 별도 로그인 기능이 없습니다.

## 4. 웹 사용

- **전체 / 그룹 / 멤버 보기**: 구성도에서 클러스터·그룹·멤버를 선택해 표시 범위를 바꿉니다. 표시 범위를 좁혀도 전체 수집과 기록은 유지됩니다.
- **리소스 패널**: 메모리·세션·SQL 처리량·네트워크 등 지표를 표시하고 패널을 추가·이동·크기 조정합니다. 제공 지표는 DB 버전·권한·수집 가능 여부에 따라 달라집니다.
- **차트**: 구간 드래그로 해당 시간대를 확대하고 원래 범위로 복원할 수 있습니다. 항목별 선 색상을 변경하며 패널별 설정을 저장합니다.
- **정보 출처**: 지원 패널의 출력 영역을 클릭해 수집 SQL 또는 수집 방법을 확인합니다.
- **Top SQL**: 수행시간·수행횟수·최대 수행시간 등의 기준으로 상위 SQL을 확인합니다.
- **SQL / 세션 / 리소스 연관 분석**: SQL·세션·자원·대기 정보를 함께 확인합니다. 목록 기본값은 10개이며 설정으로 변경할 수 있습니다.
- **락 대기**: 대기·보유 세션, 관련 SQL과 대상 객체를 확인합니다. 접속 노드와 드라이버 노드가 구분되는 정보도 함께 확인합니다.
- **진단 보고서**: 기간을 선택해 이력·이벤트·상관 정보 등을 포함한 HTML 보고서를 생성하고 저장·미리보기할 수 있습니다.

화면 갱신 일시정지는 화면만 멈추며 수집과 이력 기록은 계속됩니다. 수집 프로그램을 종료하면 수집도 종료됩니다.

## 5. 멤버 연결과 SQL Console

구성도의 멤버를 우클릭하고 **Connect**를 선택하면 별도 SQL 창이 열립니다. 팝업이 차단되면 해당 모니터링 주소의 팝업을 허용하십시오.

1. 리스너 호스트·포트·사용자·비밀번호와 접속 모드를 입력합니다.
2. 접속 성공 시 호스트·포트·사용자는 멤버별 설정에 저장합니다. SQL Console 비밀번호는 매번 입력합니다.
3. SQL을 입력하고 **실행** 또는 **Ctrl+Enter**를 누릅니다. 선택 영역이 있으면 선택한 SQL을 대상으로 합니다.
4. **결과 / Plan** 탭에서 조회 결과와 실행계획을 확인합니다.

Plan 탭은 `PLAN ONLY`로 계획을 조회하며 SQL을 실제 실행하지 않습니다. SQL 실행은 입력한 계정 권한으로 수행하며 자동 커밋이 켜져 있습니다. 결과 표시에는 최대 행 수와 셀 길이 제한이 있습니다.

객체 탐색, 지원 파일 형식의 Import/Export, SSH trace log와 관리 기능도 제공합니다. SQL 실행·데이터 Import·멤버 관리 명령은 읽기 전용 수집과 별개의 사용자 실행 작업입니다. 필요한 계정·접속 권한과 실행 내용을 확인한 후 사용하십시오.

## 6. TUI 실행

TUI는 **stty를 사용할 수 있는 Linux/Unix 터미널**을 기준으로 합니다. Windows 배포 ZIP에서도 웹은 실행할 수 있지만 네이티브 Windows CMD의 TUI 동작은 지원 범위에 포함하지 않습니다.

```sh
sh run-tui.sh
# 또는
sh run-tui.sh monitor-tui.ini
```

기본 TUI 설정도 mock이므로 처음에는 DB 없이 화면을 볼 수 있습니다. 한 번만 출력하려면 다음을 실행합니다.

```sh
sh run-tui.sh --once
```

실제 DB를 수집하려면 **TUI 전용 `monitor-tui.ini`**의 mode·url·user를 설정합니다. TUI INI에는 비밀번호 항목을 두지 않으며, JDBC 모드 시작 시 숨김 입력으로 받아 실행 중에만 사용합니다. `run-tui.sh`는 TUI 프로세스의 `MONITOR_DB_PASSWORD`를 해제합니다.

상단 요약·클러스터 구성·이벤트는 고정되고 리소스 영역을 스크롤합니다. 터미널 크기에 맞춰 레이아웃이 조정됩니다.

| 키 | 동작 |
| --- | --- |
| Tab / Shift+Tab | 패널 이동, 포커스 테두리 표시 |
| 리소스 패널 Enter → 방향키 | 패널 배치 이동 |
| 이벤트 패널 위·아래 | 이벤트 창 크기 변경 |
| 이벤트 패널 Enter → 위·아래 | 이벤트 항목 선택·스크롤 |
| 이벤트 선택 후 Enter | 상세 이벤트 열기 |
| Esc | 상세 화면·선택 모드에서 돌아가기 |
| 이벤트 패널 a | 전체 확인 처리 |
| PgUp / PgDn | 리소스 영역 이동 |
| p | 화면 일시정지·재개 |
| q | 종료 |

배치와 이벤트 확인 상태는 저장 후 다음 실행에 반영됩니다. 웹과 TUI는 별도 프로세스이며, 배포 기본 이력 경로는 웹 `output/YYYYMMDD/history/mock`·`output/YYYYMMDD/history/jdbc`, TUI `output/tui/YYYYMMDD/history/mock`·`output/tui/YYYYMMDD/history/jdbc`로 분리됩니다.

이력과 설정을 보관하려면 압축을 푼 폴더 및 data 경로에 쓰기 권한이 필요합니다. 업데이트 시 실제 INI와 이력·설정 파일을 별도로 보관하십시오. 공개 패키지에는 개인 설정·수집 이력·비밀번호·테스트 부하 데몬이 포함되지 않습니다.

## 여러 사용자의 웹 포트 설정

기본 웹 포트는 **19090**입니다. 실행할 때 다른 포트를 지정할 수 있습니다.

```sh
# Linux
sh run.sh --port 19091
sh run.sh monitor.ini --port 19092

# Windows 명령 프롬프트
run-web.cmd --port 19091

# Java 직접 실행
java -jar build/goldilocks-monitor.jar monitor.ini --port 19091
```

포트 적용 순서는 `--port` → INI의 `[monitor] port` → 기본값 `19090`입니다.
실행 옵션은 INI 파일을 변경하지 않으며, 지정 가능한 범위는 1024~65535입니다.
이미 사용 중인 포트이면 다른 포트를 선택하라는 오류를 출력하고 종료합니다.

같은 서버에서 여러 사람이 테스트할 때는 **사용자마다 별도 폴더에 압축을 풀고 서로 다른 포트로 실행**하세요. 이렇게 하면 기본 상대경로로 저장되는 수집 이력과 설정도 분리됩니다. 포트만 변경하고 같은 설정·데이터 경로를 공유하면 파일은 분리되지 않습니다.
다른 PC에서 접속하려면 INI의 `[monitor] bind`를 서버 주소 또는 `0.0.0.0`으로 설정하고 서버 방화벽에서 해당 포트의 접속을 허용하세요.


## 9. 추가된 웹 기능

### SQL 튜닝 비교

노드 SQL 창의 하단 **SQL 튜닝**에서 **SQL 분석**을 실행합니다. 실행계획과 조회 가능한 인덱스·컬럼 정보를 근거로 인덱스 접근, 형변환, 조인 순서·방식, 정렬·집계 등의 권장방안과 후보 SQL을 확인할 수 있습니다. SQL 없이 설명만 있는 행은 사용자가 검토할 사항이며 자동 실행 대상이 아닙니다.

실행할 후보 행을 명시적으로 선택하고 **선택 후보 비교**를 누르면, 확인한 원본과 후보 하나만 실행합니다. 선택하지 않은 후보나 인덱스 DDL은 실행하지 않습니다. 원본은 최대 30초, 후보는 원본 전체 결과 조회 시간의 2배를 기준으로 DB query_timeout을 적용합니다(초 단위 올림, 최소 1초). 시간 초과 후보는 제외 사유와 함께 남습니다. 비교 상태는 실행 중 강조 표시되며, 시간 초과 시 연결을 강제로 끊지 않습니다. **중지**는 실행 중 문장만 취소합니다. 노드 SQL 접속에는 IDLE_TIMEOUT=600초를 적용합니다. 후보 SQL은 복사 후 직접 편집할 수 있습니다.

### 구성도와 접속 클라이언트

구성도는 그룹과 멤버를 연결하는 트리 배치입니다. **접속노드 표시**를 켜면 외부 TCP 클라이언트 IP·접속 수를 멤버 아래 표시하며, IPC와 내부 cluster peer는 제외합니다. 클라이언트 아이콘에는 Admin 메뉴가 없습니다. 표시 설정은 브라우저에 저장됩니다.

그룹을 선택하면 해당 그룹 정보만 모니터링하면서 다른 그룹을 접어 표시합니다. 클러스터 제목의 전체 구성 규모는 유지됩니다. 멤버 선택 시 해당 멤버 상세보기로 전환하고, 클러스터 제목이나 **전체보기**를 누르면 전체 화면으로 돌아갑니다. 상세보기 중에도 전체 수집·이력 저장은 계속합니다.

### 이벤트 통계

이벤트의 **전체 확인 처리** 옆 **통계**에서 기간을 지정합니다. 보관 중인 전체 이벤트 요약을 대상으로 Event ID별·날짜별 발생 횟수를 집계합니다. 날짜는 최신순이며, 날짜를 클릭하면 그날의 Event ID별 건수를 펼치거나 접습니다. 읽음 상태는 변경하지 않습니다.

### 비활성 멤버 제거

클러스터 제목 오른쪽 **⋮ → 비활성 멤버 제거**를 선택하고 Global Coordinator에 SYSDBA로 접속합니다.

1. **제거 대상 조회**로 그룹·멤버·클러스터 주소·포트를 먼저 확인합니다.
2. **비활성 멤버 제거**를 누르고 표시된 대상과 SQL을 확인합니다.
3. `ALTER DATABASE DROP NO FORCE INACTIVE CLUSTER MEMBERS;`로 전체 비활성 멤버를 제거합니다. 단순 접속 불가(NO_RESPONSE)는 대상 판단 기준이 아닙니다.
4. 실제 제거가 확인되면 구성도에서 제외되고 **미반영 노드**에 저장됩니다. 응답이 불확실하면 **제거 결과 재확인**을 사용합니다. 이 버튼은 제거를 재실행하지 않습니다.

미반영 노드는 상세보기에서도 표시됩니다. 추가 화면에서 새 그룹 생성 또는 기존 그룹 선택을 변경할 수 있으며, 원래 그룹·주소는 기본값입니다. 등록 정보 편집 뒤 변경된 SQL을 다시 확인해야 합니다.

### 대상 노드 초기화와 재참여

노드 우클릭의 **로컬 클러스터 멤버 초기화**는 INACTIVE 또는 미반영 노드에서만 표시됩니다. 실행 직전 DB 상태와 실제 접속한 멤버 이름을 다시 검증합니다. ACTIVE·NO_RESPONSE만 있는 상태·알 수 없는 노드는 실행할 수 없습니다.

DROP된 노드를 다시 사용할 때는 해당 노드를 LOCAL OPEN까지 구동한 뒤 `ALTER DATABASE RESET LOCAL CLUSTER MEMBER;`로 초기화하고, 원하는 그룹에 새 멤버로 추가한 후 필요한 데이터 리밸런스를 수행합니다. **RESET은 테이블스페이스를 제외한 사용자 생성 객체를 제거합니다.** DROP하지 않은 장애 노드는 RESET 대신 JOIN으로 복귀할 수 있습니다. 모니터의 RESET 기능은 자동 구동·멤버 추가·JOIN·리밸런스를 수행하지 않습니다.

Admin 실패 시 비밀번호 등 입력값과 수행 버튼이 유지됩니다. 재시도마다 실행 내용을 확인하며 실행 중 중복 클릭을 차단합니다. 비밀번호는 연결 프로필이나 미반영 노드 파일에 저장하지 않습니다.


## 10. SQL 창·보고서 화면 개선

- SQL 창 왼쪽은 **스키마 → 객체 유형 → 객체** 트리입니다. 접속하면 `PUBLIC`을 기본으로 펼치고, 다른 스키마를 펼치면 해당 객체 목록을 조회합니다. 객체 상세·이름 삽입·Import/Export는 선택한 스키마를 사용합니다.
- SQL 결과 영역 맨 아래의 작은 메시지 줄에서 수행 중·성공·실패와 수행시간을 확인합니다. DDL도 성공 여부를 표시하며 오류에는 DB 메시지와 SQLSTATE·오류 코드를 표시합니다.
- 연관 분석 상세는 **Overview / SQL / Lock Status** 등 작은 제목과 흐린 회색 단락 구분선을 사용합니다. 표 선택·상세 고정·스크롤 동작은 유지됩니다.
- 이벤트 표 위 개요 문구 뒤에 **전체 확인 처리 → 통계** 버튼을 배치합니다.
- 실행 버튼은 파란색, 실제 비활성 버튼은 회색으로 구분합니다. 탭·범례의 선택 상태 색상은 별도입니다.
- 진단보고서 **생성·미리보기**는 처음부터 사용할 수 있습니다. 미리보기를 먼저 누르면 선택 기간의 보고서를 생성해 새 창에 표시하며, 같은 결과는 재사용합니다. 생성 중에는 중복 요청을 막습니다.
- 새로 생성한 HTML 보고서 맨 위에는 **PDF 저장 / 인쇄** 버튼이 있습니다. PDF 저장을 누른 뒤 브라우저 인쇄 창에서 저장 대상을 PDF로 선택합니다. 두 버튼과 언어 선택 등 조작 버튼은 실제 인쇄·PDF에 포함되지 않습니다.
- 보고서에는 `goldilocks cluster` 문구를 연한 대각선 워터마크로 표시합니다. 인쇄 시 스크롤 영역의 높이 제한을 해제하며, 출력 내용은 보고서에서 선택한 수집 시점과 표시 상태를 기준으로 합니다. 브라우저의 용지·배율·머리글/바닥글 설정은 인쇄 창에서 조정합니다.

## 기본 보관 위치

`data_dir`의 기본값은 실행 작업 디렉터리 아래 `./output`입니다. 절대 경로나 다른 상대 경로로 변경할 수 있습니다. 상대 경로는 INI 파일 위치가 아닌 실행 작업 디렉터리 기준입니다. 이벤트는 `output/YYYYMMDD/event/EVENT_ID/`에 상세·요약 파일로 저장합니다. 수집 이력은 날짜 폴더의 `history/모드/`, 실행 로그는 `log/monitor.log`에 저장합니다. 기본 보관 기간은 31일이며 설정 변경은 재시작 후 적용됩니다.

## 웹 로그인과 선택적 HTTPS

HTTP가 기본이며 웹 로그인은 기본 활성화됩니다. 최초 실행 시 `runtime/security/initial-password.txt`에서 admin 임시 암호를 확인하고 첫 로그인에서 변경하십시오. 직접 준비하는 초기 암호 파일도 지원하며 기존 파일을 덮어쓰지 않습니다. 모든 비밀 파일은 본인만 접근할 수 있게 설정하십시오. 설정과 초기화 방법은 [WEB_AUTH_GUIDE](docs/WEB_AUTH_GUIDE.md), 내부 CA·PEM·PKCS12 HTTPS 설정은 [INTERNAL_CA_HTTPS_GUIDE](docs/INTERNAL_CA_HTTPS_GUIDE.md)에 있습니다. HTTPS keystore 암호는 대화형 숨김 입력 또는 별도 파일/환경변수로 받으며 INI 평문 암호는 지원하지 않습니다.

수집용 DB 암호도 `[goldilocks] password_file = /private/path/db-password`로 별도 파일(UTF-8 한 줄, 권한 600/400)에 둘 수 있습니다. 파일 경로는 INI 기준이며 `~/`도 지원합니다. 기존 `MONITOR_DB_PASSWORD`가 우선합니다. 파일을 변경하면 재시작하십시오.

SQL 가져오기는 먼저 유효한 DB 콘솔 세션을 확인하고 `[console] max_import_bytes`(기본 16MiB), `import_body_timeout_seconds`(기본 30초) 제한을 적용합니다. 원시 SQL과 이력·내보내기 파일에는 업무 정보가 포함될 수 있으므로 별도로 접근·공유를 관리하십시오. 지원 중인 최신 보안 패치 JRE를 사용하십시오.

### 패널 출력물을 지목하는 에이전트 요청

- `Top SQL에 1순위 분석해줘`, `Top SQL 두 번째 플랜 보여줘`, `Top SQL 2번 튜닝`을 지원합니다. 대시보드 Top SQL의 현재 정렬(누적시간·실행횟수·관측 최대시간)과 실제 표시 순서를 사용하며, 에이전트의 느린 SQL 순위와 혼동하지 않습니다.
- `방금 Top SQL 첫 번째 분석`은 앞서 대화에 출력한 SQL 결과를 참조합니다. 과거 이력 SQL은 행별 원래 관측 스냅샷을 유지합니다. 선택한 행·멤버·관측 시각을 답변에 표시하고 기존 SQL/세션/락/자원 연관분석 및 별도 상세·계획·튜닝 창에 연결합니다. 실행계획은 기존 DB 인증을 거치며 SQL을 자동 실행하지 않습니다.
- `세션 패널 분석`, `공유 메모리 패널 설명`, `트랜잭션 패널 첫 번째 분석`, `테이블스페이스 패널 보여줘`, `락 패널 첫 번째 분석`처럼 표시된 패널을 지정할 수 있습니다. 사용자 정의 표는 현재 표시 행을 요약하며 사용자 정의 차트의 행 분석은 아직 지원하지 않습니다.
- 여러 패널이나 행 중 대상을 확정할 수 없으면 선택 버튼을 제공합니다. 존재하지 않는 행·다른 멤버·수집 실패는 이전 값으로 대체하지 않습니다. 지원하지 않는 작업은 명시적으로 안내합니다. 차트는 임의로 행 순위를 만들지 않으며 현재값 요약과 구간 분석을 구분합니다. 기존 SQL OPS 구간 분석은 차트에서 구간을 선택합니다.
- 대시보드 기본 갱신·DB 수집에 쿼리를 추가하지 않습니다. 요청 시 현재 표시 컨텍스트를 읽으며 Top SQL 표시 행 참조는 최대 24개 패널로 제한합니다. 누적값을 구간 차분이나 CPU 사용량으로 해석하지 않습니다.

대시보드 왼쪽 상단 제목을 `GOLDILOCKS ADMIN`으로 통일하고 계정·로그아웃을 제목 아래에 배치했습니다. 해당 브랜드 영역에 마우스가 5초 이상 머물면 현재 포인터 옆에 `오늘도 무사히...`가 1초 동안 나타납니다. 일찍 영역을 벗어나면 취소하며 같은 진입에서 반복 표시하지 않습니다.

### 대화에서 이전 시간 구간을 이어받는 SQL 분석

`최근 5분간 가장 많이 수행된 쿼리 찾아줘` 다음에 `그 시간대 느려진 쿼리 찾아줘`, `해당 시간대에 새로 등장한 쿼리는?`처럼 물을 수 있습니다. 이전 질문의 절대 시작·종료 시각을 유지하므로 후속 질문 때 최근 구간이 현재 시각으로 밀리지 않습니다. 이벤트 조회의 `08:40~08:50` 구간도 이어받습니다. 명시적 시각은 오늘 기준, 상대 구간은 최대 24시간이며 시작 포함·종료 제외입니다. 멤버는 기존 원칙대로 질문마다 지정하며 생략하면 전체 멤버입니다.

- 새로 관측된 SQL: 멤버별 SQL 원문을 인접한 시작 기준 관측과 비교합니다. 기준이 없으면 최초 관측 후보일 뿐 신규 SQL이라고 확정하지 않습니다. SQL 생성·최초 실행 시각을 뜻하지 않습니다.
- 가장 많이 수행된 SQL: 세션·보존 SQL 항목의 유효한 연속 관측 쌍에서 실행횟수 증가량을 합산합니다. 처음 보인 누적값이나 초기화 전후 차이는 구간 부하로 계산하지 않습니다. 계산된 관측 범위와 쌍 수를 표시합니다.
- 느려진 SQL: 기존 SQL OPS 구간 분석 엔진의 마지막 수행시간 증가 판정을 재사용합니다. 카운터 세대·멤버 ID 변경·SQL 소멸·긴 공백을 넘어 비교하지 않고, 실제 실행횟수 증가가 관측된 경우만 후보로 삼습니다. 기준·최대 수행시간 및 각각의 관측 시각을 표시합니다.

분석은 사용자 요청 시 별도 Web Worker에서 이미 적재된 이력만 처리합니다(최대 5만 SQL행·추정 16MiB, 취소 지원). DB 추가 조회나 31일 전체 파일 조회를 하지 않습니다. 과거 구간이 적재되지 않았다면 대시보드에서 해당 이력을 먼저 불러와야 합니다. 보존 SQL 샘플은 전체 DB 실행 로그가 아니며 캐시에서 사라진 SQL, 잘린 SQL 원문, 다운샘플링·수집 실패로 관측하지 못한 작업은 복원할 수 없습니다. 부족한 데이터는 0이나 미발생으로 바꾸지 않습니다. 결과의 상세 버튼은 행을 관측한 원래 스냅샷으로 연관분석을 엽니다.

약 0.95~1.23MiB의 버전별 자료는 명시적 매뉴얼 조회 때 로컬 서버에서만 불러옵니다. 기본 대시보드 초기 표시/자동 수집에 요청이나 DB 질의를 추가하지 않습니다. 같은 버전은 캐시·동시 요청 공유를 사용하고, 실패 시 재시도와 취소/시간 제한을 지원합니다. 원문 HTML/Markdown 표를 텍스트로 변환해 실행 가능한 HTML이나 SQL로 취급하지 않습니다.

agent 상세 팝업은 로그아웃/언어 선택 컨트롤을 표시하지 않으며 기존 웹 인증·권한·세션 가드는 유지합니다. 로그아웃은 메인 대시보드에서 수행합니다.

수집설정의 리소스 표에서 화면 표시, 이력 저장, 소리 알림을 각각 선택할 수 있습니다. 이력 저장은 기본적으로 모두 켜져 있으며, 끄더라도 현재 값 수집·표시 및 이벤트 감지는 계속됩니다. 저장을 끈 이후의 해당 리소스 이력만 생략하고 기존 이력을 삭제하지 않습니다. 소리 설정은 브라우저별로 적용되며, 해당 리소스의 이벤트가 없는 항목은 소리 열에 `—`로 표시합니다.

### DB assistant의 향후 관측 작업

- `전체멤버대상으로 앞으로 5분간 공유메모리 사용량 평균을 구해줘`: 창을 닫아도 기존 수집 스냅샷으로 멤버별 평균을 계산합니다. 중복·누락·오류 샘플을 구분하며 누락을 0으로 계산하지 않습니다. 멤버별 사용량·할당량·사용률은 유효 샘플의 산술평균이고, 전체 사용률은 모든 대상 멤버가 관측된 샘플에서 할당량을 기준으로 가중 계산합니다. 시간 가중 평균은 아닙니다.
- `앞으로 5분간 SQL OPS가 현재대비 10% 떨어지면 알려줘`, `G1N1 앞으로 10분간 세션수가 현재대비 10% 오르면 알려줘`: 등록 시점의 기준값을 고정하고 상대 변화율로 비교합니다. 사용량 100에서 10% 상승은 110, 하락은 90입니다. 공유메모리 사용량(GiB)·사용률(%)·세션 수·SQL OPS를 지원합니다. 사용률의 10% 상승도 상대 변화이며 10%p 상승과 다릅니다. 전체 멤버는 각 초기 멤버의 기준값으로 비교하여 하나가 처음 충족하면 완료합니다.
- 기간·변화율이 없거나 방향이 모호한 요청은 실행하지 않습니다. 기준값이 없거나 0인 경우 상대 변화율 작업을 등록하지 않습니다. 이미 지난 기간의 평균 계산 기능을 의미하지 않습니다.
- 작업은 동시 최대 4개이며 추가 DB 쿼리를 실행하지 않습니다. 완료 결과는 메인 이벤트에도 저장됩니다. 서버 재시작 시 진행 중 작업은 중단 결과로 남고 관측하지 못한 시간을 정상 감시로 간주하지 않습니다.
- 목록은 요청 날짜·시각, 대상, 상태, 종료 예정, 결과를 표로 표시합니다. 완료 작업은 삭제할 수 있으며 이미 기록된 완료 이벤트는 유지합니다. 실행 중 작업은 먼저 취소해야 합니다. 새로고침 버튼은 상태 문구와 간격을 두었습니다.

`SQL OPS가 현재 대비 -10% 이상 떨어지면`도 10% 하락 조건으로 해석합니다. 성능 저하의 기준 지표가 생략된 경우에는 처리량 감소인지 실행시간 증가인지 지정하도록 안내하며 임의의 지표로 작업을 등록하지 않습니다. `-10% 상승`처럼 부호와 방향이 충돌하는 조건은 등록하지 않습니다.

수집설정 우측 패널은 기본 폭을 넓히고 작은 화면에서는 화면 너비에 맞춥니다. 리소스명은 왼쪽, 나머지 열은 가운데 정렬하며 표와 설정 영역을 연한 선으로 구분합니다. 저장 결과는 버튼 아래에 표시합니다.

상세 결과는 assistant·이벤트창에서 같은 표 스타일과 글꼴을 사용하며 정보 영역 사이를 연한 선으로 구분합니다. 백그라운드 결과서에는 요청 날짜·시각, 대상, 종료 예정 및 완료 시각을 공통 표시합니다. `네가 수행가능한 백그라운드 명령은 무엇이 있지?` 또는 `백그라운드 작업 도움말`을 물으면 지원하는 작업 4종과 예문만 표시하고 작업을 등록하지 않습니다. 대화창 상단 고정 정보와 하단 작업·입력 영역에도 구분선 및 여백을 적용했습니다.

### DB assistant의 읽기 전용 테이블·뷰 조회

`V$SESSION에서 USER_NAME이 TEST인 세션 보여줘` 또는 `SELECT SESSION_ID, USER_NAME FROM V$SESSION WHERE USER_NAME = 'TEST'`처럼 요청할 수 있습니다. 수집 설정의 DB URL·계정·비밀번호 파일을 재사용하여 별도 연결에서 조회하며, 전체 멤버 일괄 조회나 다른 멤버로의 자동 접속을 의미하지 않습니다. DB 접속·조회 권한이 없으면 오류를 표시합니다. 명확히 해석하지 못한 조건은 SQL을 검토·수정하도록 하며 일부 조건만 적용해서 자동 실행하지 않습니다.

assistant 경로에서는 서버가 작은 SELECT 문법을 직접 파싱하여 다시 생성하고 값을 PreparedStatement로 바인딩합니다. 단일 테이블·뷰의 컬럼/전체 컬럼/COUNT·MIN·MAX·SUM·AVG, 단순 WHERE 비교·AND·OR·IN·IS NULL, ORDER BY를 지원합니다. 임의 함수·서브쿼리·CTE·일반 조인·주석/힌트·다중 문장·SELECT INTO/FOR UPDATE·시퀀스·프로시저·파일/OS 명령·DDL 및 INSERT/UPDATE/DELETE/MERGE/COPY 등을 실행하지 않습니다. JDBC 읽기 전용 설정과 DB `SET TRANSACTION READ ONLY`가 성공한 경우에만 조회하고 연결 종료 전 rollback합니다. 수동 SQL 콘솔은 기존 별도 기능입니다.

`V$TRANSACTION에서 1분간 사라지지 않는 세션 보여줘`는 식별 키 컬럼을 입력받은 뒤 행 관측 작업으로 등록합니다. 예를 들어 TRANS_ID와 SESSION_ID를 이용할 수 있으며 대상 객체에서 실제로 유일한 키를 지정해야 합니다. 첫 유효 조회의 행을 이후 조회와 교집합으로 비교하며 사라졌다 다시 나온 행은 다시 포함하지 않습니다. 중복·NULL 키, 조회 실패·누락·행/셀/용량 잘림은 데이터 부족으로 구분합니다. 실제 관측 구간을 결과에 표시하며 수집 사이에도 연속 존재했음을 보증하지 않습니다. 서버 재시작 시 진행 작업은 중단 처리하고 재조회하지 않습니다. 기존 작업과 합쳐 동시 최대4개입니다. 목록에는 요약만 전송하고 행 결과는 상세 선택 시 조회합니다.

`[assistant]` 설정: `enabled=true`, `query_timeout_seconds=5`(1–30), `max_rows=200`(1–500), `max_bytes=1048576`(1024–2097152), `query_interval_seconds=10`(5–3600). 기본 대시보드 수집에 질의를 추가하지 않으며 명시적 조회/관측 요청 때만 별도2작업자·4대기열에서 수행합니다. 실제 실행 제한은 JDBC의 질의/네트워크 타임아웃을 사용합니다. 결과와 관측 SQL에는 업무 데이터가 포함될 수 있으며 서버의 기존 로컬 작업 보관 위치에 저장됩니다. 비밀번호를 작업 데이터에 저장하지 않습니다.

트랜잭션 관측에서 프로그램명을 요청하면 검증된 `V$TRANSACTION`↔`V$SESSION`의 `SESSION_ID` 일치 조인만 예외적으로 허용합니다. `유지되는`, `종료되지 않는`, `사라지지 않는`을 같은 관측 요청으로 해석합니다. TRANS_ID·TRANS_SEQ·SESSION_ID·SERIAL_NO를 추천 식별 키로 표시하며 결과 컬럼은 SQL에서 선택할 수 있습니다. 자연어 행 관측은 복합 조건 누락을 방지하기 위해 SQL의 모든 조건과 식별 키를 확인한 후 등록합니다.


### 노드별 독립 관찰과 수집 연결 자동 전환

수집설정 마지막의 **노드정보 수정**에서 알려진 노드의 IP/호스트, **리스너 포트**, DB 사용자 및 비밀번호를 입력합니다. 클러스터 통신 포트를 리스너 포트로 사용하지 않습니다. 기존에 정상 접속해 보관한 SQL 콘솔 연결 정보가 있으면 기본값으로 표시하며, 없는 리스너 포트는 직접 입력해야 합니다. 수집 비밀번호 사용을 선택하면 기존 수집 계정의 비밀번호 파일/환경 설정을 재사용합니다. 별도 비밀번호 입력란을 비워 저장하면 기존 별도 비밀번호를 유지합니다.

연결 정보는 INI 기준 경로의 `.cluster-observer-connections.properties`에 원자적으로 저장합니다. `[cluster_observer] credentials_file`로 경로를 변경할 수 있습니다. 비밀번호는 숨김 파일의 평문이므로 서버 파일 접근 권한이 보호 경계입니다. POSIX에서는 소유자 읽기/쓰기만, Windows에서는 소유자 전용 ACL만 허용하며, 화면/API에 비밀번호를 반환하지 않고 소스·배포 패키지에도 포함하지 않습니다. 다른 서버로 복사할 때에는 연결 정보와 파일 권한을 별도로 설정해야 합니다.

기본 수집은 계속 **하나의 노드 연결**을 사용합니다. 수집 노드의 접속 실패 또는 연결 단절이 발생하면 설정된 다른 노드에 순서대로 접속하고 노드 이름을 확인하여 첫 정상 연결에서 수집을 재시도합니다. 정상 전환 후에는 해당 노드를 유지하며 원래 노드로 매번 되돌아가지 않습니다. SQL 문법/권한 오류를 접속 장애로 간주하여 전환하지 않습니다. 재접속에는 제한 시간이 있고, 실패가 계속되면 다음 주기에 후보 탐색을 이어갑니다. 모든 후보가 실패하면 기존 마지막 구성도/오류 표시를 유지합니다. DB 전체를 중단하거나 접속을 강제로 이동시키는 기능은 아닙니다.

실제 전환은 `COLLECTOR_FAILOVER` 이벤트와 스냅샷 `collectorConnection`에 기록합니다. `sourceChanged` 및 `collectionGap`으로 전환/공백을 구분하고, 해당 시점의 누적 카운터·SQL/진단 캐시 기준을 초기화하여 이전 접속과 새 접속 사이의 잘못된 증가량 계산을 피합니다. 장애 감지·새 접속 중 수집 공백은 생길 수 있으며 무중단 관측을 보증하지 않습니다. 웹 화면과 과거 이력은 유지합니다. 독립 관찰을 꺼도 저장된 연결은 수집 자동 전환에 사용할 수 있습니다. SQL 콘솔/assistant의 별도 연결 정책은 변경하지 않습니다.

**독립 노드 관찰**은 기본 꺼짐이며 연결정보를 저장하고 켤 수 있습니다. 기본 30초 간격, 연결 제한 3초로 별도 2개 작업자가 각 노드의 로컬 `V$CLUSTER_MEMBER`와 `V$AGABLE_INFO.GLOBAL_SCN`을 읽습니다. 일반 수집 경로와 웹 요청 스레드에서 이 조회를 기다리지 않습니다. 접속 노드의 이름을 확인하고 읽기 전용 트랜잭션에서 조회 후 rollback/close합니다. 동시·대기 작업 수와 관찰 회차의 제한 시간을 둡니다.

성공한 서로 다른 노드가 각각 자신을 ACTIVE, 상대를 INACTIVE로 보고하면 `CLUSTER_INTERCONNECT_SUSPECTED`, 서로 다른 활성 Global Coordinator까지 확인되면 `CLUSTER_SPLIT_BRAIN_SUSPECTED`의 후보가 됩니다. **두 차례 연속 관찰** 후 이벤트를 기록하며 동일한 지속 상태는 반복 발행하지 않습니다. 실패한 회차는 연속 확인을 끊고, 정상 복구 후 재발하면 다시 기록합니다. 접속 실패·인증 실패·조회 실패·미설정은 네트워크 분할의 증거로 단정하지 않습니다. 현재 구현은 기본 수집의 최신 멤버 ID 매핑이 유효해야 비교하므로 기본 수집도 실패하거나 구성이 바뀌어 매핑이 불확실한 구간은 판정할 수 없습니다.

각 노드의 실제 조회 시작/종료 시각을 보존하고, 서로의 시작/종료 시각 차이가 15초를 넘거나 오래된 관측은 비교하지 않습니다. `GLOBAL_SCN`은 원문 문자열을 보존합니다. 26c 소스의 표현은 `GCN.DCN.LCN`이며, 첫 값의 차이만으로 split-brain을 단정하지 않습니다. 이 기능은 sampled local view의 **의심 징후**를 보여주며 물리 케이블 단절이나 split-brain 확정 판정을 의미하지 않습니다. 20c/21c의 해당 뷰·컬럼과 계정 권한은 실제 환경에서 확인해야 하며 실패 시 관찰 실패로 표시합니다.

자동 테스트는 정상/불일치 관점, 서로 다른 coordinator, 관측 지연, 중복 이벤트 억제, 제한 시간, 비밀번호 비노출, 설정 복원, 연결 전환/유지/전체 실패 및 차분 기준 초기화를 검증합니다. 실제 클러스터 장애/네트워크 분할 시험은 별도 검증이 필요합니다.

### 행 관측의 식별 컬럼 제안

`V$TRANSACTION` 외의 테이블/뷰도 행 관측 검토창에서 식별 컬럼을 제안합니다. 검증된 전체 기본 키를 우선 사용하고, 알려진 시스템 뷰의 키 또는 ID 계열 이름으로 추정한 후보는 근거를 구분해 표시합니다. 기본 키 일부만 조회했거나 컬럼명이 중복되는 결과는 완전한 기본 키로 표시하지 않습니다. 추정 후보는 실제 유일성/재사용 여부를 사용자가 확인해야 하며 자동으로 작업을 시작하지 않습니다. 임의의 유일성을 보증하거나 알 수 없는 키를 0으로 대체하지 않습니다.

명시적 검토 때만 `/api/agent/read-columns`가 별도 제한된 작업자에서 JDBC 준비문 메타데이터와 기본 키 정보를 조회합니다. 해당 업무 SELECT의 행은 실행/가져오기하지 않습니다. 수동 입력한 식별 키를 비동기 응답으로 덮어쓰지 않으며 SQL 변경 후 다시 찾을 수 있습니다. 기본 대시보드 초기 수집에는 메타데이터 조회를 추가하지 않습니다.

노드정보 수정 표에는 DB 접속정보 옆에 SSH ID·비밀번호·포트를 입력할 수 있습니다. SSH 대상 호스트는 같은 행의 IP/호스트를 사용하고 포트 기본값은 22입니다. SSH 비밀번호도 동일한 소유자 전용 비공개 파일에 보관하며 API에는 저장 여부만 반환합니다. 비밀번호를 비워 저장하면 기존 값을 유지합니다. 기존 파일과 이전 양식의 저장 요청도 호환됩니다. SSH 수집을 활성화하고 노드정보를 저장하면 해당 화면에서 호스트 지문을 확인·승인할 수 있습니다. 승인된 노드는 OS 자원을 별도로 수집하고 메인 System trace 패널이 표시될 때 trace에 자동 연결합니다.


### 메인 System trace 패널

리소스 추가에서 `System trace (SSH)`를 선택합니다. 수집설정의 노드정보에 DB·SSH 접속정보를 저장하고 SSH 수집을 활성화하면 패널이 승인된 노드에 자동 연결합니다. SSH 수집이 활성화된 대상 노드 모두에 자동 연결하며 시스템 Trace·SQL Trace·관리 Trace의 동시 연결 개수에는 고정 제한을 두지 않습니다. 최초 접속/호스트 키 변경 시 노드정보 저장 화면에서 표시된 SHA256 지문을 확인하고 승인해야 합니다. 로그인된 관리자만 연결할 수 있습니다.

저장된 해당 노드의 DB에 읽기 전용으로 접속해 실제 노드 이름을 확인하고 로컬 `V$PROPERTY`의 `TRACE_SYSTEM_DIR`을 조회합니다. 서버가 이 디렉터리의 `system.trc`만 SSH `tail -n 100 -F`로 읽으며 임의 명령/파일 경로를 브라우저에서 받지 않습니다. SQL 창의 경로 조회·SSH tail·TraceLog 파싱/검색/필터를 공통으로 사용합니다. 모니터 서버의 로컬 경로를 원격 노드 경로로 추측하지 않습니다.

여러 노드의 로그를 시간 내림차순으로 합쳐 시간·노드 이름·THREAD·세션 ID·분류·메시지를 표시합니다. 메인 패널은 표만 표시하며 기본50행/페이지입니다. 원문·파일 경로·연결/지문 승인 UI는 없으며 분류/스레드/태그 필터는 표 헤더에 유지합니다. 최대32,000개 표 항목과8MiB 예산 중 먼저 도달한 한도부터 오래된 로그 시각 순으로 제거합니다. 여러 줄 메시지는 한 항목으로 계산하고8192자까지 보관합니다. 누락된 로그 시각은 해당 노드의 직전 헤더 시각을 따릅니다. 테이블 DOM은 해당 페이지의50행만 생성합니다. SQL 콘솔 Trace의 기존 기본2000줄/최대20000줄 설정은 바꾸지 않습니다. 원격 tail 버퍼도 연결별500줄/256KiB로 제한하여 소비가 늦으면 누락을 표시합니다.

일반 수집·대시보드 초기 표시에는 SSH/속성 조회를 추가하지 않습니다. 패널이 표시되고 활성 노드의 접속정보와 지문 승인이 준비됐을 때 제한된 별도 작업자에서 접속하며, 폴링은 약2초 간격이고 겹친 요청을 막습니다. 패널 제거/재구성/범위 변경/창 종료는 스트림을 닫고, 폴링이 없는 연결은 기존60초 만료 정책을 따릅니다. `tail -F`로 파일 교체를 따라가며 접속이 끝나면 상태와 재연결 기능을 표시합니다. 이 패널 로그 자체를 JSONL 이력에 중복 저장하지 않으며 과거 리소스 화면에서는 제외합니다.

수신된 로그 헤더 분류가 `FATAL`, `ABORT`인 항목은 `SYSTEM_TRACE_FATAL`, `SYSTEM_TRACE_ABORT` 이벤트로 저장합니다. 다른 버전의 명시적 `CRITICAL` 헤더도 호환 처리합니다. 본문에 이 단어가 있다는 이유만으로 이벤트를 만들지 않습니다. 헤더 이후 여러 줄의 내용을 최대8192자로 모아 별도의128개 대기열 작업자가 저장하며, 로그 시간·노드·메시지로 재접속/재시작 중복을 막습니다. 시간은 로그의 현지 시각을 모니터 서버 시간대로 해석하며 잘못된 시각은 관측 시각을 사용하고 이를 표시합니다. 연결해 읽고 있는 스트림만 감지하며 SSH 미연결 기간 전체를 보장하지 않습니다. 처음 가져오는100줄에 보관 기간 내 FATAL/ABORT가 있으면 원래 로그 시간으로 등록합니다.

승인된 소스 기반 메시지도 수신된 로그에서 찾아 이벤트로 등록합니다. 테이블스페이스 부족·데드락·세션 정리·타임아웃·Coordinator Failover·멤버 INACTIVE를 구분합니다. FATAL/ABORT/CRITICAL 분류가 있으면 우선하여 한 로그 항목에서 중복 이벤트를 만들지 않습니다. 대상 문구는 `[DEADLOCK]`, `deadlock detected`, `[FAILOVER] ... coordinator failover`, `sniped session`, `sniped remote session`, `[TABLESPACE] datafile extending failed`, `Tablespace(...) is full`, `there is no extendible datafile in tablespace`, `cluster protocol response timeout`, `Exceeded maximum query time`, `Exceeded maximum idle time`, `resource busy or timeout expired`입니다. 오류 메시지 테이블에 존재하는 문구가 항상 system.trc에 기록되는 것은 아니며 호출 경로와 레벨/에러 스택에 따라 달라집니다. 단순 FAILOVER/timeout 전체 매칭은 정상 진행/idle 종료도 포함할 수 있습니다. 현재26c 공통 로그 레벨 소스는 FATAL/ABORT/WARNING/INFORMATION이며 CRITICAL은 확인되지 않았습니다.


### 지속 SSH 연결을 이용한 OS 자원

노드정보의 **SSH 수집 활성화**를 켜고 SSH ID·비밀번호·포트를 저장합니다(기본 꺼짐). 최초 호스트 키는 노드정보 저장 과정에서 확인·승인합니다. 승인되지 않은 호스트에는 OS 수집이 자동 접속하지 않으며 `HOST_KEY_REQUIRED`를 표시합니다. 비활성화하면 새 조회를 중단하고 해당 노드 연결을 닫습니다.

승인된 노드별 SSH 연결을 유지하고 OS 자원 조회와 Trace가 같은 연결의 별도 채널을 사용합니다. 자원 조회마다 SSH 인증을 반복하지 않으며, 접속정보 변경/실제 연결 단절 시에만 재연결합니다. `[ssh_collection] interval_seconds=10`이 기본이며 5~300초로 변경할 수 있습니다. 별도2개 작업자/4개 대기열에서 고정된 읽기 전용 Linux `/proc`·`/sys` 조회와 `df -Pk`만 실행하며 임의 명령을 받지 않습니다. 조회 채널은3초/256KiB 한도이고 기본 DB 수집은 대기하지 않습니다.

기존 CPU 패널은 **호스트 전체 CPU 사용률**을 표시합니다(첫 샘플·초기화 시 계산 불가). `Host memory`, `Data file volume usage`, `Host disk read/write`, `Host network RX/TX`도 리소스 메뉴에서 추가할 수 있습니다. DB 공유메모리/테이블스페이스/내부 통신 패널과 별개입니다. 디스크 I/O는 파티션·device-mapper 중복을 제외한 전체 물리 장치를 사용하고, 네트워크는 물리 인터페이스 우선/명시적 non-loopback 대안을 구분합니다. 같은 서버의 여러 DB 노드는 같은 호스트 자원을 보는 것이며 DB별 CPU 사용량으로 해석하지 않습니다.

실제 SSH 관측 시각·오류·대상 호스트를 각 노드에 보존하고, 기본30초 이상 오래된 값/미수집/실패는 0으로 채우지 않습니다. JSONL에는 숫자 메트릭과 상태를 남기며 파일시스템·디바이스·NIC별 상세 배열은 현재 화면용으로만 유지하여 이력 증가를 줄입니다. 리소스별 이력 저장 스위치도 따릅니다. 현재 구현은 Linux의 해당 가상 파일 형식을 전제로 합니다.

SQL·세션 연관분석의 현재 보기 컨트롤 아래에는 연한 구분선을 표시하고, SQL 표 헤더는 내부 스크롤 영역 상단에 고정합니다.

상단4개 요약 카드와 클러스터 구성도에는 크기 조절 손잡이를 제공합니다. 순서/위치는 유지하고 폭·높이만 변경하며, 크기는 브라우저에 저장합니다. 구성도 그림과 요약 내용은 패널에 맞춰 표시하고 좁은 화면에서는 사용 가능한 공간으로 제한합니다. 기존 리소스 패널 배치는 변경하지 않습니다.


### 배치 가능한 현재 스냅샷 카드

멤버 상태·접속 세션·공유메모리·SQL 처리량도 같은 리소스 패널 유형입니다. 상단4개 카드는 기본 구성을 유지하되 마우스를 올리거나 키보드로 포커스하면 나타나는 선택 메뉴에서 다른 기본 리소스/사용자 정의 리소스로 교체할 수 있습니다. 이미 다른 상단 카드에 있는 항목을 선택하면 두 카드가 교환됩니다. 비어 있는 슬롯도 선택할 수 있습니다. 구성은 서버의 `dashboard-summary.properties`에 저장됩니다.

패널 추가에서 **배치 위치(리소스 영역/상단 요약)**와 **표시 방식(차트/현재 스냅샷)**을 선택합니다. 상단 요약은 현재 스냅샷 카드만 사용하고, 멤버 상태는 현재 스냅샷, System trace는 원래 표 형태로 제한합니다. 리소스 영역에는 동일 리소스의 차트와 현재 스냅샷을 각각 하나씩 배치할 수 있으며, 동일 리소스·동일 표시 방식의 중복은 막습니다. 기존 저장 구성은 차트로 해석하고, 알려진 UID를 보낸 이전 양식이 표시 방식을 생략해도 기존 값을 보존합니다.

현재값 카드는 이미 수집된 스냅샷만 사용하며 새 DB 질의나 수집 주기를 추가하지 않습니다. 사용자 정의 리소스는 기존 숫자 시리즈/선택된 숫자 컬럼을 표시하고, 인증 필요·누락·증감 기준 미확립은 유효한0으로 채우지 않습니다. 호스트 자원 카드는 실제 SSH 관측 시각을 사용합니다. 상단 카드의 기존 식별자/기본 UI는 호환성을 유지하며, 교체한 항목과 축소 글꼴·아이콘도 패널 비례 축소를 따릅니다.

메인 System trace 패널은 자동 폭 조절에 의해 축소되지 않고 오른쪽 작업 영역 전체 열을 차지합니다. 다른 리소스 패널의 자동 폭 배치는 그대로 유지합니다.


### DATAFILE / 로그 볼륨과 Trace 노드 필터

디스크 용량 패널은 루트 파일시스템이 아니라 DB가 사용하는 볼륨을 표시합니다. 활성 노드의 로컬 `V$DATAFILE.DATAFILE_NAME`, `V$LOGFILE.FILE_NAME`, `V$PROPERTY.LOG_DIR / GLOBAL_TRANSACTION_LOG_DIR`을 읽기 전용으로 조회하여 실제 경로의 상위 마운트를 찾습니다. 메타데이터는 노드·접속 설정별60초 캐시를 사용하고 DB 조회 실패가 CPU·메모리 수집을 중단시키지 않습니다. 데이터/로그가 여러 볼륨이면 역할별 목록과 최대 사용률을 표시합니다. 같은 실제 볼륨이면 두 역할에 같은 사용률이 표시되며 더하지 않습니다. 경로가 없으면 사용률을0이나 무관한루트값으로 대체하지 않습니다.

`hostDisk`는 데이터파일 볼륨, `hostLogDisk`는 WAL/redo·global transaction log 볼륨입니다. 기본수집에는 별도메타데이터질의를추가하지않고 SSH활성노드의분리된작업자에서만조회합니다. 현재조회상태와DB경로/파일시스템/마운트역할은노드정보에서확인할수있습니다.

System trace는 전체 SSH 활성 노드에서 읽으며 대시보드의 그룹/멤버 선택과 독립적인 노드 필터를 제공합니다. 표의 노드 헤더에서 전체/개별 노드를 선택할 수 있고 보관된 모든 페이지를 대상으로 분류·스레드·태그 필터와 조합합니다. 이 패널에는 리소스 출처 팝업을 표시하지 않습니다. 시간 내림차순의 첫50행에 일부 노드만 보이더라도 해당 노드 필터로 더 오래된 로그를 확인할 수 있습니다.


### DB assistant의 수집 근거 기반 원인 추론

`top10 SQL에 1위 쿼리가 느린 원인을 찾아줘`는 현재 표시 순위·정렬을 유지한 SQL을 대상으로 분석합니다. `전반적으로 지연되는 쿼리를 찾아서 원인을 찾아줘`는 관측된 마지막 실행시간으로 선택한 SQL 중 최대 3개의 관련 근거를 교차 확인합니다. 세션 식별자가 일치하는 락 차단·현재 WAITING, 관련 노드의 호스트 CPU·공유메모리 할당·DB 저장 볼륨 용량, 누적 통계에 대한 마지막 실행시간 변화 가능성을 원인 후보·근거 수준·관측 시각·다음 확인사항으로 표시합니다. 실행시간은 CPU 사용량이 아니며 호스트 자원은 SQL 단독 사용량이 아닙니다. 누적 평균과의 비교도 구간 증가량 분석을 대신하지 않습니다.

사용자 요청 때 브라우저에 이미 적재된 관측값만 분석하며 추가 DB 질의·외부 AI 호출·기본 갱신 작업은 없습니다. 프로브별 최대 1,000행을 확인하며 SQL/근거 시각이 현재보다 30초 이상 오래되거나 서로 30초 이상 차이나면 현재 원인의 근거로 사용하지 않습니다. 수집 실패·비활성화 및 세션 재사용을 구분하고, 누적 대기는 현재 대기와 별도의 참고 정황으로 표시합니다. 근거 수준은 규칙에 따른 분류이며 확률이 아닙니다. 원인이 입증되지 않은 정황을 확정 원인으로 표현하지 않습니다.

`클러스터 네트워크 사용량이 높은 세션을 찾아줘`는 내부 RX+TX가 큰 노드와 그 노드에서 수집된 관련 SQL·세션 후보를 제공합니다. 일반 네트워크 질문은 내부 통신량과 SSH 호스트 NIC 통신량을 구분합니다. 세션별 네트워크 바이트 통계는 없어 사용량 순위로 표현하지 않으며, 이 경로의 과거 세션별 네트워크 분석은 지원하지 않습니다.


매뉴얼 검색은 패키지에 포함된 색인을 사용하며 외부 웹 연결 없이 동작합니다. `transaction_timeout 설명`, `트랜잭션 타임아웃 설명 찾아줘`처럼 한글·영문·혼합 개념으로 실제 속성명을 찾고, 후보가 여러 개이면 선택하도록 표시합니다. 런타임 패널·SQL 분석과 감시 요청은 매뉴얼 안내로 바꾸지 않습니다. `20c`, `21c`, `26c` 자료는 기존 선택 버전을 유지합니다.

시스템 trace의 노드·분류·스레드·태그 필터는 각 열 제목의 다음 줄에 정렬합니다. SSH trace 연결 개수 제한은 제거했지만 연결별 로그 버퍼, 메인 표의 32,000항목·8MiB 한도, 읽지 않는 연결의 60초 회수는 유지합니다.


### 과거이력 이벤트 전체 탐색

과거이력의 이벤트 날짜를 조회하면 해당 일자의 저장된 이벤트 **요약만** 시간 내림차순(동일 시각은 이벤트 ID 내림차순)으로 200개씩 표시합니다. 이전·다음 버튼으로 최근200개 제한 밖의 이벤트도 끝까지 탐색합니다. 현재 페이지의 표만 유지하며, 상세 파일은 행을 클릭했을 때 `/api/diagnostics?id=...`에서 가져옵니다. 이벤트 본문·스냅샷 전체를 목록 응답에 포함하지 않습니다.

전용 `/api/history/events`는 선택 일자의 디렉터리 및 이전 형식의 요약 파일 이름만 순회하고, 페이지에 필요한 요약만 읽습니다. SQL·자원 JSONL이나 다른 날짜의 상세 파일은 읽지 않으며 대시보드 갱신과 별도 작업자에서 처리합니다. 순서 키를 가진 서명된 커서로 다음 페이지를 찾고, 같은 시각의 여러 이벤트와 이전 형식 중복을 처리합니다. 보관 만료·손상된 요약은 표시하고 손상된 항목이 있는 페이지도 다음 페이지로 진행할 수 있습니다. 페이지 조회 실패 시 현재 표를 유지하고 다시 시도할 수 있습니다. 모니터 재시작으로 커서가 만료되면 날짜를 다시 조회합니다.
