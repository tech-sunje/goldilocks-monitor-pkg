# GOLDILOCKS Monitor / goldilocks Admin

GOLDILOCKS 클러스터의 상태·리소스·SQL·세션·대기 이벤트를 확인하는 **Java 8 기반 웹/TUI 모니터**입니다. DB 서버에 모니터링 에이전트를 설치하지 않고 외부 관리 PC 또는 별도 서버에서 실행합니다.

이 저장소는 실행 패키지·체크섬·사용법만 공개 배포합니다. 개발용 Java 소스와 비공개 소스 저장소의 Git 이력은 포함하지 않습니다.

## 1. 준비

- **Java 8 이상(JRE)**과 웹 브라우저가 필요합니다.
- 압축을 해제한 후 실행합니다. 쓰기 가능한 폴더를 사용하십시오.
- 실행에 JDK·컴파일러·Python·Node.js는 필요하지 않습니다.
- JDBC 드라이버와 필요한 라이브러리·라이선스 문서는 패키지에 포함됩니다.
- 배포 기본값은 **mock 모드·127.0.0.1:19090**이며 실제 DB에 접속하지 않습니다. 실제 접속정보·비밀번호·수집 이력은 포함하지 않습니다.

## 2. 웹 실행

### Windows

1. ZIP을 다운로드하고 압축을 풉니다.
2. `java -version`으로 Java 8 이상인지 확인합니다.
3. `goldilocks-monitor` 폴더의 **`run-web.cmd`**를 더블클릭합니다.
4. 실행 창에 표시된 주소를 브라우저에서 엽니다. 기본 주소는 **http://127.0.0.1:19090**입니다.

다른 INI를 지정하려면 명령 프롬프트에서 실행합니다.

```bat
run-web.cmd C:\monitor\my-monitor.ini
```

`java`를 찾을 수 없다면 Java 실행 경로를 PATH에 추가하거나 JAVA_HOME을 설정하십시오. 실행 스크립트는 JAVA_HOME이 있으면 해당 Java를 사용합니다.

### Linux

```sh
tar -xzf goldilocks-monitor-linux.tar.gz
cd goldilocks-monitor
sh run.sh
```

다른 설정 파일도 지정할 수 있습니다.

```sh
sh run.sh /path/to/my-monitor.ini
```

직접 JAR로 실행하려면 압축을 푼 폴더에서 다음을 사용합니다. `build/`와 `lib/`의 상대 위치는 유지하십시오.

```sh
java -jar build/goldilocks-monitor.jar monitor.ini
```

브라우저 탭을 닫아도 수집 프로그램은 실행 상태를 유지합니다. 프로그램을 종료할 때는 실행 터미널에서 **Ctrl+C**를 누릅니다. 이미 19090 포트를 사용하는 프로그램이 있으면 INI의 포트를 바꿉니다.

## 3. 실제 GOLDILOCKS 연결

웹용 `monitor.ini`에서 mock을 jdbc로 바꾸고 실제 리스너 주소와 조회 계정을 설정합니다.

```ini
[monitor]
mode = jdbc
name = GOLDILOCKS Cluster
bind = 127.0.0.1
port = 19090

[collection]
interval_seconds = 3
retention_days = 31
data_dir = ./output

[goldilocks]
url = jdbc:goldilocks://<접속호스트>:<리스너포트>/test
user = <모니터링계정>
password =
```

수집에 사용하는 계정은 필요한 클러스터·시스템 통계 뷰를 조회할 수 있어야 합니다. 권한이나 버전에 따라 조회할 수 없는 지표는 N/A 또는 수집 오류로 표시될 수 있습니다.

웹 수집 비밀번호는 기존 INI 방식 또는 `MONITOR_DB_PASSWORD` 환경변수로 전달합니다. 웹의 기존 인증 방식은 유지됩니다. 비밀번호를 공개 저장소에 올리지 마십시오.

Linux 환경변수 예시:

```sh
read -r -s -p 'DB password: ' MONITOR_DB_PASSWORD
export MONITOR_DB_PASSWORD
printf '\n'
sh run.sh
```

INI 변경은 수집 프로세스를 재시작한 뒤 적용합니다. 상대 경로는 INI 위치를 기준으로 해석합니다. 다른 PC에서 웹에 접속해야 한다면 운영 환경의 접근 제어를 구성한 뒤 bind 값을 조정하십시오. 기본 대시보드 HTTP 화면에는 별도 로그인 기능이 없습니다.

## 4. 웹 사용

- **전체 / 그룹 / 멤버 보기**: 구성도에서 클러스터·그룹·멤버를 선택해 표시 범위를 바꿉니다. 표시 범위를 좁혀도 전체 수집과 기록은 유지됩니다.
- **리소스 패널**: 메모리·세션·SQL 처리량·네트워크 등 지표를 표시하고 패널을 추가·이동·크기 조정합니다. 제공 지표는 DB 버전·권한·수집 가능 여부에 따라 달라집니다.
- **차트**: 구간 드래그로 해당 시간대를 확대하고 원래 범위로 복원할 수 있습니다. 항목별 선 색상을 변경하며 패널별 설정을 저장합니다.
- **정보 출처**: 지원 패널의 출력 영역을 클릭해 수집 SQL 또는 수집 방법을 확인합니다.
- **Top SQL**: 수행시간·수행횟수·최대 수행시간 등의 기준으로 상위 SQL을 확인합니다.
- **SQL / 세션 / 리소스 연관 분석**: SQL·세션·자원·대기 정보를 함께 확인합니다. 목록 기본값은 10개이며 설정으로 변경할 수 있습니다.
- **락 대기**: 대기·보유 세션, 관련 SQL과 대상 객체를 확인합니다. 접속 노드와 드라이버 노드가 구분되는 정보도 함께 확인합니다.
- **진단 보고서**: 기간을 선택해 이력·이벤트·상관 정보 등을 포함한 HTML 보고서를 생성하고 저장·미리보기할 수 있습니다.

화면 갱신 일시정지는 화면만 멈추며 수집과 이력 기록은 계속됩니다. 수집 프로그램을 종료하면 수집도 종료됩니다.

## 5. 멤버 연결과 SQL Console

구성도의 멤버를 우클릭하고 **Connect**를 선택하면 별도 SQL 창이 열립니다. 팝업이 차단되면 해당 모니터링 주소의 팝업을 허용하십시오.

1. 리스너 호스트·포트·사용자·비밀번호와 접속 모드를 입력합니다.
2. 접속 성공 시 호스트·포트·사용자는 멤버별 설정에 저장합니다. SQL Console 비밀번호는 매번 입력합니다.
3. SQL을 입력하고 **실행** 또는 **Ctrl+Enter**를 누릅니다. 선택 영역이 있으면 선택한 SQL을 대상으로 합니다.
4. **결과 / Plan** 탭에서 조회 결과와 실행계획을 확인합니다.

Plan 탭은 `PLAN ONLY`로 계획을 조회하며 SQL을 실제 실행하지 않습니다. SQL 실행은 입력한 계정 권한으로 수행하며 자동 커밋이 켜져 있습니다. 결과 표시에는 최대 행 수와 셀 길이 제한이 있습니다.

객체 탐색, 지원 파일 형식의 Import/Export, SSH trace log와 관리 기능도 제공합니다. SQL 실행·데이터 Import·멤버 관리 명령은 읽기 전용 수집과 별개의 사용자 실행 작업입니다. 필요한 계정·접속 권한과 실행 내용을 확인한 후 사용하십시오.

## 6. TUI 실행

TUI는 **stty를 사용할 수 있는 Linux/Unix 터미널**을 기준으로 합니다. Windows 배포 ZIP에서도 웹은 실행할 수 있지만 네이티브 Windows CMD의 TUI 동작은 지원 범위에 포함하지 않습니다.

```sh
sh run-tui.sh
# 또는
sh run-tui.sh monitor-tui.ini
```

기본 TUI 설정도 mock이므로 처음에는 DB 없이 화면을 볼 수 있습니다. 한 번만 출력하려면 다음을 실행합니다.

```sh
sh run-tui.sh --once
```

실제 DB를 수집하려면 **TUI 전용 `monitor-tui.ini`**의 mode·url·user를 설정합니다. TUI INI에는 비밀번호 항목을 두지 않으며, JDBC 모드 시작 시 숨김 입력으로 받아 실행 중에만 사용합니다. `run-tui.sh`는 TUI 프로세스의 `MONITOR_DB_PASSWORD`를 해제합니다.

상단 요약·클러스터 구성·이벤트는 고정되고 리소스 영역을 스크롤합니다. 터미널 크기에 맞춰 레이아웃이 조정됩니다.

| 키 | 동작 |
| --- | --- |
| Tab / Shift+Tab | 패널 이동, 포커스 테두리 표시 |
| 리소스 패널 Enter → 방향키 | 패널 배치 이동 |
| 이벤트 패널 위·아래 | 이벤트 창 크기 변경 |
| 이벤트 패널 Enter → 위·아래 | 이벤트 항목 선택·스크롤 |
| 이벤트 선택 후 Enter | 상세 이벤트 열기 |
| Esc | 상세 화면·선택 모드에서 돌아가기 |
| 이벤트 패널 a | 전체 확인 처리 |
| PgUp / PgDn | 리소스 영역 이동 |
| p | 화면 일시정지·재개 |
| q | 종료 |

배치와 이벤트 확인 상태는 저장 후 다음 실행에 반영됩니다. 웹과 TUI는 별도 프로세스이며, 배포 기본 이력 경로는 웹 `output/YYYYMMDD/history/mock`·`output/YYYYMMDD/history/jdbc`, TUI `output/tui/YYYYMMDD/history/mock`·`output/tui/YYYYMMDD/history/jdbc`로 분리됩니다.

이력과 설정을 보관하려면 압축을 푼 폴더 및 data 경로에 쓰기 권한이 필요합니다. 업데이트 시 실제 INI와 이력·설정 파일을 별도로 보관하십시오. 공개 패키지에는 개인 설정·수집 이력·비밀번호·테스트 부하 데몬이 포함되지 않습니다.


## 여러 사용자의 웹 포트 설정

기본 웹 포트는 **19090**입니다. 실행할 때 다른 포트를 지정할 수 있습니다.

```sh
# Linux
sh run.sh --port 19091
sh run.sh monitor.ini --port 19092

# Windows 명령 프롬프트
run-web.cmd --port 19091

# Java 직접 실행
java -jar build/goldilocks-monitor.jar monitor.ini --port 19091
```

포트 적용 순서는 `--port` → INI의 `[monitor] port` → 기본값 `19090`입니다.
실행 옵션은 INI 파일을 변경하지 않으며, 지정 가능한 범위는 1024~65535입니다.
이미 사용 중인 포트이면 다른 포트를 선택하라는 오류를 출력하고 종료합니다.

같은 서버에서 여러 사람이 테스트할 때는 **사용자마다 별도 폴더에 압축을 풀고 서로 다른 포트로 실행**하세요. 이렇게 하면 기본 상대경로로 저장되는 수집 이력과 설정도 분리됩니다. 포트만 변경하고 같은 설정·데이터 경로를 공유하면 파일은 분리되지 않습니다.
다른 PC에서 접속하려면 INI의 `[monitor] bind`를 서버 주소 또는 `0.0.0.0`으로 설정하고 서버 방화벽에서 해당 포트의 접속을 허용하세요.


## 9. 추가된 웹 기능

### SQL 튜닝 비교

노드 SQL 창의 하단 **SQL 튜닝**에서 **SQL 분석**을 실행합니다. 실행계획과 조회 가능한 인덱스·컬럼 정보를 근거로 인덱스 접근, 형변환, 조인 순서·방식, 정렬·집계 등의 권장방안과 후보 SQL을 확인할 수 있습니다. SQL 없이 설명만 있는 행은 사용자가 검토할 사항이며 자동 실행 대상이 아닙니다.

실행할 후보 행을 명시적으로 선택하고 **선택 후보 비교**를 누르면, 확인한 원본과 후보 하나만 실행합니다. 선택하지 않은 후보나 인덱스 DDL은 실행하지 않습니다. 원본은 최대 30초, 후보는 원본 전체 결과 조회 시간의 2배를 기준으로 DB query_timeout을 적용합니다(초 단위 올림, 최소 1초). 시간 초과 후보는 제외 사유와 함께 남습니다. 비교 상태는 실행 중 강조 표시되며, 시간 초과 시 연결을 강제로 끊지 않습니다. **중지**는 실행 중 문장만 취소합니다. 노드 SQL 접속에는 IDLE_TIMEOUT=600초를 적용합니다. 후보 SQL은 복사 후 직접 편집할 수 있습니다.

### 구성도와 접속 클라이언트

구성도는 그룹과 멤버를 연결하는 트리 배치입니다. **접속노드 표시**를 켜면 외부 TCP 클라이언트 IP·접속 수를 멤버 아래 표시하며, IPC와 내부 cluster peer는 제외합니다. 클라이언트 아이콘에는 Admin 메뉴가 없습니다. 표시 설정은 브라우저에 저장됩니다.

그룹을 선택하면 해당 그룹 정보만 모니터링하면서 다른 그룹을 접어 표시합니다. 클러스터 제목의 전체 구성 규모는 유지됩니다. 멤버 선택 시 해당 멤버 상세보기로 전환하고, 클러스터 제목이나 **전체보기**를 누르면 전체 화면으로 돌아갑니다. 상세보기 중에도 전체 수집·이력 저장은 계속합니다.

### 이벤트 통계

이벤트의 **전체 확인 처리** 옆 **통계**에서 기간을 지정합니다. 보관 중인 전체 이벤트 요약을 대상으로 Event ID별·날짜별 발생 횟수를 집계합니다. 날짜는 최신순이며, 날짜를 클릭하면 그날의 Event ID별 건수를 펼치거나 접습니다. 읽음 상태는 변경하지 않습니다.

### 비활성 멤버 제거

클러스터 제목 오른쪽 **⋮ → 비활성 멤버 제거**를 선택하고 Global Coordinator에 SYSDBA로 접속합니다.

1. **제거 대상 조회**로 그룹·멤버·클러스터 주소·포트를 먼저 확인합니다.
2. **비활성 멤버 제거**를 누르고 표시된 대상과 SQL을 확인합니다.
3. `ALTER DATABASE DROP NO FORCE INACTIVE CLUSTER MEMBERS;`로 전체 비활성 멤버를 제거합니다. 단순 접속 불가(NO_RESPONSE)는 대상 판단 기준이 아닙니다.
4. 실제 제거가 확인되면 구성도에서 제외되고 **미반영 노드**에 저장됩니다. 응답이 불확실하면 **제거 결과 재확인**을 사용합니다. 이 버튼은 제거를 재실행하지 않습니다.

미반영 노드는 상세보기에서도 표시됩니다. 추가 화면에서 새 그룹 생성 또는 기존 그룹 선택을 변경할 수 있으며, 원래 그룹·주소는 기본값입니다. 등록 정보 편집 뒤 변경된 SQL을 다시 확인해야 합니다.

### 대상 노드 초기화와 재참여

노드 우클릭의 **로컬 클러스터 멤버 초기화**는 INACTIVE 또는 미반영 노드에서만 표시됩니다. 실행 직전 DB 상태와 실제 접속한 멤버 이름을 다시 검증합니다. ACTIVE·NO_RESPONSE만 있는 상태·알 수 없는 노드는 실행할 수 없습니다.

DROP된 노드를 다시 사용할 때는 해당 노드를 LOCAL OPEN까지 구동한 뒤 `ALTER DATABASE RESET LOCAL CLUSTER MEMBER;`로 초기화하고, 원하는 그룹에 새 멤버로 추가한 후 필요한 데이터 리밸런스를 수행합니다. **RESET은 테이블스페이스를 제외한 사용자 생성 객체를 제거합니다.** DROP하지 않은 장애 노드는 RESET 대신 JOIN으로 복귀할 수 있습니다. 모니터의 RESET 기능은 자동 구동·멤버 추가·JOIN·리밸런스를 수행하지 않습니다.

Admin 실패 시 비밀번호 등 입력값과 수행 버튼이 유지됩니다. 재시도마다 실행 내용을 확인하며 실행 중 중복 클릭을 차단합니다. 비밀번호는 연결 프로필이나 미반영 노드 파일에 저장하지 않습니다.


## 10. SQL 창·보고서 화면 개선

- SQL 창 왼쪽은 **스키마 → 객체 유형 → 객체** 트리입니다. 접속하면 `PUBLIC`을 기본으로 펼치고, 다른 스키마를 펼치면 해당 객체 목록을 조회합니다. 객체 상세·이름 삽입·Import/Export는 선택한 스키마를 사용합니다.
- SQL 결과 영역 맨 아래의 작은 메시지 줄에서 수행 중·성공·실패와 수행시간을 확인합니다. DDL도 성공 여부를 표시하며 오류에는 DB 메시지와 SQLSTATE·오류 코드를 표시합니다.
- 연관 분석 상세는 **Overview / SQL / Lock Status** 등 작은 제목과 흐린 회색 단락 구분선을 사용합니다. 표 선택·상세 고정·스크롤 동작은 유지됩니다.
- 이벤트 표 위 개요 문구 뒤에 **전체 확인 처리 → 통계** 버튼을 배치합니다.
- 실행 버튼은 파란색, 실제 비활성 버튼은 회색으로 구분합니다. 탭·범례의 선택 상태 색상은 별도입니다.
- 진단보고서 **생성·미리보기**는 처음부터 사용할 수 있습니다. 미리보기를 먼저 누르면 선택 기간의 보고서를 생성해 새 창에 표시하며, 같은 결과는 재사용합니다. 생성 중에는 중복 요청을 막습니다.
- 새로 생성한 HTML 보고서 맨 위에는 **PDF 저장 / 인쇄** 버튼이 있습니다. PDF 저장을 누른 뒤 브라우저 인쇄 창에서 저장 대상을 PDF로 선택합니다. 두 버튼과 언어 선택 등 조작 버튼은 실제 인쇄·PDF에 포함되지 않습니다.
- 보고서에는 `goldilocks cluster` 문구를 연한 대각선 워터마크로 표시합니다. 인쇄 시 스크롤 영역의 높이 제한을 해제하며, 출력 내용은 보고서에서 선택한 수집 시점과 표시 상태를 기준으로 합니다. 브라우저의 용지·배율·머리글/바닥글 설정은 인쇄 창에서 조정합니다.

## 기본 보관 위치

`data_dir`의 기본값은 실행 작업 디렉터리 아래 `./output`입니다. 절대 경로나 다른 상대 경로로 변경할 수 있습니다. 상대 경로는 INI 파일 위치가 아닌 실행 작업 디렉터리 기준입니다. 이벤트는 `output/YYYYMMDD/event/EVENT_ID/`에 상세·요약 파일로 저장합니다. 수집 이력은 날짜 폴더의 `history/모드/`, 실행 로그는 `log/monitor.log`에 저장합니다. 기본 보관 기간은 31일이며 설정 변경은 재시작 후 적용됩니다.

## 웹 로그인과 선택적 HTTPS

HTTP가 기본이며 웹 로그인은 기본 활성화됩니다. 최초 실행 시 `runtime/security/initial-password.txt`에서 admin 임시 암호를 확인하고 첫 로그인에서 변경하십시오. 직접 준비하는 초기 암호 파일도 지원하며 기존 파일을 덮어쓰지 않습니다. 모든 비밀 파일은 본인만 접근할 수 있게 설정하십시오. 설정과 초기화 방법은 [WEB_AUTH_GUIDE](docs/WEB_AUTH_GUIDE.md), 내부 CA·PEM·PKCS12 HTTPS 설정은 [INTERNAL_CA_HTTPS_GUIDE](docs/INTERNAL_CA_HTTPS_GUIDE.md)에 있습니다. HTTPS keystore 암호는 대화형 숨김 입력 또는 별도 파일/환경변수로 받으며 INI 평문 암호는 지원하지 않습니다.

수집용 DB 암호도 `[goldilocks] password_file = /private/path/db-password`로 별도 파일(UTF-8 한 줄, 권한 600/400)에 둘 수 있습니다. 파일 경로는 INI 기준이며 `~/`도 지원합니다. 기존 `MONITOR_DB_PASSWORD`가 우선합니다. 파일을 변경하면 재시작하십시오.

SQL 가져오기는 먼저 유효한 DB 콘솔 세션을 확인하고 `[console] max_import_bytes`(기본 16MiB), `import_body_timeout_seconds`(기본 30초) 제한을 적용합니다. 원시 SQL과 이력·내보내기 파일에는 업무 정보가 포함될 수 있으므로 별도로 접근·공유를 관리하십시오. 지원 중인 최신 보안 패치 JRE를 사용하십시오.

### 패널 출력물을 지목하는 에이전트 요청

- `Top SQL에 1순위 분석해줘`, `Top SQL 두 번째 플랜 보여줘`, `Top SQL 2번 튜닝`을 지원합니다. 대시보드 Top SQL의 현재 정렬(누적시간·실행횟수·관측 최대시간)과 실제 표시 순서를 사용하며, 에이전트의 느린 SQL 순위와 혼동하지 않습니다.
- `방금 Top SQL 첫 번째 분석`은 앞서 대화에 출력한 SQL 결과를 참조합니다. 과거 이력 SQL은 행별 원래 관측 스냅샷을 유지합니다. 선택한 행·멤버·관측 시각을 답변에 표시하고 기존 SQL/세션/락/자원 연관분석 및 별도 상세·계획·튜닝 창에 연결합니다. 실행계획은 기존 DB 인증을 거치며 SQL을 자동 실행하지 않습니다.
- `세션 패널 분석`, `공유 메모리 패널 설명`, `트랜잭션 패널 첫 번째 분석`, `테이블스페이스 패널 보여줘`, `락 패널 첫 번째 분석`처럼 표시된 패널을 지정할 수 있습니다. 사용자 정의 표는 현재 표시 행을 요약하며 사용자 정의 차트의 행 분석은 아직 지원하지 않습니다.
- 여러 패널이나 행 중 대상을 확정할 수 없으면 선택 버튼을 제공합니다. 존재하지 않는 행·다른 멤버·수집 실패는 이전 값으로 대체하지 않습니다. 지원하지 않는 작업은 명시적으로 안내합니다. 차트는 임의로 행 순위를 만들지 않으며 현재값 요약과 구간 분석을 구분합니다. 기존 SQL OPS 구간 분석은 차트에서 구간을 선택합니다.
- 대시보드 기본 갱신·DB 수집에 쿼리를 추가하지 않습니다. 요청 시 현재 표시 컨텍스트를 읽으며 Top SQL 표시 행 참조는 최대 24개 패널로 제한합니다. 누적값을 구간 차분이나 CPU 사용량으로 해석하지 않습니다.

대시보드 왼쪽 상단 제목을 `GOLDILOCKS ADMIN`으로 통일하고 계정·로그아웃을 제목 아래에 배치했습니다. 해당 브랜드 영역에 마우스가 5초 이상 머물면 현재 포인터 옆에 `오늘도 무사히...`가 1초 동안 나타납니다. 일찍 영역을 벗어나면 취소하며 같은 진입에서 반복 표시하지 않습니다.

### 대화에서 이전 시간 구간을 이어받는 SQL 분석

`최근 5분간 가장 많이 수행된 쿼리 찾아줘` 다음에 `그 시간대 느려진 쿼리 찾아줘`, `해당 시간대에 새로 등장한 쿼리는?`처럼 물을 수 있습니다. 이전 질문의 절대 시작·종료 시각을 유지하므로 후속 질문 때 최근 구간이 현재 시각으로 밀리지 않습니다. 이벤트 조회의 `08:40~08:50` 구간도 이어받습니다. 명시적 시각은 오늘 기준, 상대 구간은 최대 24시간이며 시작 포함·종료 제외입니다. 멤버는 기존 원칙대로 질문마다 지정하며 생략하면 전체 멤버입니다.

- 새로 관측된 SQL: 멤버별 SQL 원문을 인접한 시작 기준 관측과 비교합니다. 기준이 없으면 최초 관측 후보일 뿐 신규 SQL이라고 확정하지 않습니다. SQL 생성·최초 실행 시각을 뜻하지 않습니다.
- 가장 많이 수행된 SQL: 세션·보존 SQL 항목의 유효한 연속 관측 쌍에서 실행횟수 증가량을 합산합니다. 처음 보인 누적값이나 초기화 전후 차이는 구간 부하로 계산하지 않습니다. 계산된 관측 범위와 쌍 수를 표시합니다.
- 느려진 SQL: 기존 SQL OPS 구간 분석 엔진의 마지막 수행시간 증가 판정을 재사용합니다. 카운터 세대·멤버 ID 변경·SQL 소멸·긴 공백을 넘어 비교하지 않고, 실제 실행횟수 증가가 관측된 경우만 후보로 삼습니다. 기준·최대 수행시간 및 각각의 관측 시각을 표시합니다.

분석은 사용자 요청 시 별도 Web Worker에서 이미 적재된 이력만 처리합니다(최대 5만 SQL행·추정 16MiB, 취소 지원). DB 추가 조회나 31일 전체 파일 조회를 하지 않습니다. 과거 구간이 적재되지 않았다면 대시보드에서 해당 이력을 먼저 불러와야 합니다. 보존 SQL 샘플은 전체 DB 실행 로그가 아니며 캐시에서 사라진 SQL, 잘린 SQL 원문, 다운샘플링·수집 실패로 관측하지 못한 작업은 복원할 수 없습니다. 부족한 데이터는 0이나 미발생으로 바꾸지 않습니다. 결과의 상세 버튼은 행을 관측한 원래 스냅샷으로 연관분석을 엽니다.

## 2026-10-29 최신 변경사항

### Database Information 매뉴얼 검색 보강

`V$SESSION 설명이 메뉴얼에 있나?`, `PERFORMANCE_VIEW_SCHEMA.V$SESSION`, `V$SESSION SESSION_STATUS 컬럼 설명`, 기존 매뉴얼 색인 표기(`V$SESSION@V00048;PERFORMANCE_VIEW_SCHEMA`)를 뷰·스키마 식별자로 해석합니다. 20c 279개 / 21c 282개 / 26c 349개의 Database Information 뷰·테이블 설명과 컬럼 표를 버전별 원문 출처로 표시합니다. V$와 GV$를 동일한 객체로 추정하지 않습니다. 일반 SQL Reference/목차 검색과 실제 수집 세션·SQL 분석은 유지합니다. 매뉴얼 전체 본문 검색을 의미하지는 않습니다.

약 0.95~1.23MiB의 버전별 자료는 명시적 매뉴얼 조회 때 로컬 서버에서만 불러옵니다. 기본 대시보드 초기 표시/자동 수집에 요청이나 DB 질의를 추가하지 않습니다. 같은 버전은 캐시·동시 요청 공유를 사용하고, 실패 시 재시도와 취소/시간 제한을 지원합니다. 원문 HTML/Markdown 표를 텍스트로 변환해 실행 가능한 HTML이나 SQL로 취급하지 않습니다.

생성: `python3 tools/build-manual-references.py --manual20 /path/to/manual20-db.json --manual21 /path/to/manual21-db.json --manual26 /path/to/9-database-information.md --property20 /path/to/manual20-property.json --property21 /path/to/manual21-property.json --property26 /path/to/10-server-property.md`. 각 자료의 해시와 26c 원본 커밋을 JSON provenance에 기록합니다.

agent 상세 팝업은 로그아웃/언어 선택 컨트롤을 표시하지 않으며 기존 웹 인증·권한·세션 가드는 유지합니다. 로그아웃은 메인 대시보드에서 수행합니다.

수집설정의 리소스 표에서 화면 표시, 이력 저장, 소리 알림을 각각 선택할 수 있습니다. 이력 저장은 기본적으로 모두 켜져 있으며, 끄더라도 현재 값 수집·표시 및 이벤트 감지는 계속됩니다. 저장을 끈 이후의 해당 리소스 이력만 생략하고 기존 이력을 삭제하지 않습니다. 소리 설정은 브라우저별로 적용되며, 해당 리소스의 이벤트가 없는 항목은 소리 열에 `—`로 표시합니다.

Server Property도 버전별로 오프라인 색인에 포함합니다(20c 243개 / 21c 257개 / 26c 284개). `property에 idle_timeout 설명해줘`와 같은 질문에는 해당 버전의 설명, 기본값·범위·변경 가능 여부 및 출처를 표시합니다. 표시값은 매뉴얼 정보이며 현재 DB 설정값을 조회하지 않습니다. 요청 시 외부 매뉴얼 서버에 접속하지 않으며, 기존 SQL·시스템 뷰 검색과 수집 데이터 분석은 유지합니다.

### DB assistant의 향후 관측 작업

- `전체멤버대상으로 앞으로 5분간 공유메모리 사용량 평균을 구해줘`: 창을 닫아도 기존 수집 스냅샷으로 멤버별 평균을 계산합니다. 중복·누락·오류 샘플을 구분하며 누락을 0으로 계산하지 않습니다. 멤버별 사용량·할당량·사용률은 유효 샘플의 산술평균이고, 전체 사용률은 모든 대상 멤버가 관측된 샘플에서 할당량을 기준으로 가중 계산합니다. 시간 가중 평균은 아닙니다.
- `앞으로 5분간 SQL OPS가 현재대비 10% 떨어지면 알려줘`, `G1N1 앞으로 10분간 세션수가 현재대비 10% 오르면 알려줘`: 등록 시점의 기준값을 고정하고 상대 변화율로 비교합니다. 사용량 100에서 10% 상승은 110, 하락은 90입니다. 공유메모리 사용량(GiB)·사용률(%)·세션 수·SQL OPS를 지원합니다. 사용률의 10% 상승도 상대 변화이며 10%p 상승과 다릅니다. 전체 멤버는 각 초기 멤버의 기준값으로 비교하여 하나가 처음 충족하면 완료합니다.
- 기간·변화율이 없거나 방향이 모호한 요청은 실행하지 않습니다. 기준값이 없거나 0인 경우 상대 변화율 작업을 등록하지 않습니다. 이미 지난 기간의 평균 계산 기능을 의미하지 않습니다.
- 작업은 동시 최대 4개이며 추가 DB 쿼리를 실행하지 않습니다. 완료 결과는 메인 이벤트에도 저장됩니다. 서버 재시작 시 진행 중 작업은 중단 결과로 남고 관측하지 못한 시간을 정상 감시로 간주하지 않습니다.
- 목록은 요청 날짜·시각, 대상, 상태, 종료 예정, 결과를 표로 표시합니다. 완료 작업은 삭제할 수 있으며 이미 기록된 완료 이벤트는 유지합니다. 실행 중 작업은 먼저 취소해야 합니다. 새로고침 버튼은 상태 문구와 간격을 두었습니다.

`SQL OPS가 현재 대비 -10% 이상 떨어지면`도 10% 하락 조건으로 해석합니다. 성능 저하의 기준 지표가 생략된 경우에는 처리량 감소인지 실행시간 증가인지 지정하도록 안내하며 임의의 지표로 작업을 등록하지 않습니다. `-10% 상승`처럼 부호와 방향이 충돌하는 조건은 등록하지 않습니다.

수집설정 우측 패널은 기본 폭을 넓히고 작은 화면에서는 화면 너비에 맞춥니다. 리소스명은 왼쪽, 나머지 열은 가운데 정렬하며 표와 설정 영역을 연한 선으로 구분합니다. 저장 결과는 버튼 아래에 표시합니다.
